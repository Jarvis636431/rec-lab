# LR CTR 补充笔记：类别不平衡与正则化

这份笔记记录当前 LR 基线进入真实 CTR 场景前必须理解的两个问题：低点击率带来的类别不平衡，以及高维稀疏特征带来的过拟合。

## 当前基线提供了什么

当前默认实验包含 20,000 条模拟曝光，整体 CTR 约为 10.28%。数据按时间切分为训练、验证和测试集，并且只使用训练集统计量完成标准化。

它已经适合验证：

- logits、Sigmoid 与 BCE 的关系；
- 反向传播和 SGD 更新；
- AUC、LogLoss 与 ECE；
- 人工交叉特征对 LR 的帮助。

但它只有 5～6 个稳定特征，正样本也不算极端稀少，因此暂时没有充分展示类别不平衡和过拟合。

## 问题一：类别不平衡

### 为什么不能只看 Accuracy？

当 CTR 为 1% 时，永远预测“不点击”也能获得 99% Accuracy，但模型没有召回任何点击，也没有有效排序能力。

当前实验优先报告：

```text
AUC      → 排序能力
LogLoss  → 概率预测质量
ECE      → 预测概率与实际频率的差距
```

进一步处理极低 CTR 时，可以补充 PR-AUC、Precision 和 Recall。

### 负采样解决什么？

负采样主要用于减少大量未点击曝光带来的存储与计算成本，并提高每个 Batch 看到正样本的频率。它不是免费的数据增强：丢弃负样本会提高训练集中的正样本占比，使模型输出偏离线上真实 CTR。

若每个负样本以概率 `s` 保留，采样分布中的预测为 `q`，原始概率为：

```text
p = s × q / (1 - q + s × q)
```

因此只对训练集采样；验证集和测试集应尽量保留真实分布，用于评估 LogLoss、CTR 和校准。

### `pos_weight` 解决什么？

PyTorch 的正类加权可以写成：

```python
criterion = nn.BCEWithLogitsLoss(pos_weight=positive_weight)
```

它让一个正样本错误产生更大的损失，从而改变模型对漏掉正样本与误报负样本的权衡。常见起点是：

```text
positive_weight = 负样本数 / 正样本数
```

但这不是固定答案，应由验证集表现和业务成本决定。加权损失也会改变概率含义，因此必须重新检查 predicted CTR、LogLoss 和 ECE。

### 负采样和加权怎样选择？

| 需求 | 更直接的方法 |
| --- | --- |
| 数据太大、训练太慢 | 负采样 |
| 希望更重视正样本错误 | `pos_weight` |
| 修正已知采样概率 | 每样本权重或概率修正 |
| 概率参与业务价值计算 | 在真实分布验证集上校准 |

无论使用哪种方法，都要记录采样率、权重、数据分布和指标口径。

## 问题二：过拟合与正则化

### LR 为什么也会过拟合？

LR 的结构简单，但工业 CTR 模型可能拥有百万甚至亿级稀疏参数。大量 ID、低频类别和人工交叉特征会让模型记住训练集中的偶然关系。

典型信号是：

```text
Train Loss 继续下降
Validation Loss 开始上升
```

当前实验没有明显过拟合，是因为样本多、特征少、数据规律稳定，不代表 LR 天然不会过拟合。

### L2 正则化

L2 目标为：

```text
L_total = L_BCE + λ Σ wᵢ²
```

它持续压缩较大的权重，使模型不容易过度依赖单个特征。在当前 SGD 优化器中可以先这样实验：

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=args.learning_rate,
    weight_decay=1e-4,
)
```

正式实现时建议把 `weight_decay` 暴露为命令行参数，并考虑不对 bias 使用同样的衰减。

### L1 正则化

L1 目标为：

```text
L_total = L_BCE + λ Σ |wᵢ|
```

它倾向把不重要特征的权重推向零，适合观察稀疏化和特征选择。可以在训练循环中显式加入：

```python
l1_penalty = model.linear.weight.abs().sum()
loss = criterion(logits, batch_y) + l1_strength * l1_penalty
```

训练日志需要区分纯 BCE 与包含正则项的总 Loss，否则不同实验之间的损失不可直接解释。

### Early Stopping

每轮训练后检查 Validation Loss：

```text
有改善     → 保存模型，patience 归零
没有改善   → patience 加一
达到上限   → 停止并恢复最佳模型
```

测试集不能参与停止条件或超参数选择，否则最终测试指标会带有数据泄漏。

## 推荐的后续实验

这些实验应在进入 FM 前后逐步完成，而不是一次把所有机制塞进训练脚本。

### 实验 A：准确率陷阱

1. 将模拟数据的基础 CTR 调低。
2. 增加“全部预测为 0”的 Accuracy 基线。
3. 同时报告 AUC、PR-AUC、LogLoss 和 Recall。
4. 解释为什么 99% Accuracy 仍可能是无效模型。

### 实验 B：负采样与概率修正

1. 只对训练集负采样，记录负样本保留率 `s`。
2. 在未采样测试集上直接评估预测概率。
3. 使用采样率公式修正概率后重新评估。
4. 对比 AUC、LogLoss、ECE 和 predicted CTR。

预期现象：概率修正前后 AUC 基本不变，LogLoss、ECE 和 predicted CTR 明显变化。

### 实验 C：L2 与噪声特征

1. 加入一批与标签无关的噪声特征。
2. 对比 `weight_decay = 0、1e-5、1e-4、1e-3`。
3. 记录 Train/Validation Loss、AUC 和权重范数。
4. 使用验证集选择强度，只在最后查看测试集。

预期现象：适量 L2 限制噪声权重并改善泛化；过强 L2 导致欠拟合。

### 实验 D：L1 稀疏化

1. 保留同一批噪声特征。
2. 比较不同 L1 强度下接近零的权重数量。
3. 同时观察有效特征是否也被错误压制。

## 实现前检查清单

- [ ] 采样只作用于训练集。
- [ ] 记录原始 CTR、采样后 CTR 和负样本保留率。
- [ ] 区分采样修正、样本权重和概率校准。
- [ ] 报告 AUC 的同时报告概率类指标。
- [ ] 正则化超参数只通过验证集选择。
- [ ] 日志区分数据损失与正则化后的总损失。
- [ ] Early Stopping 恢复最佳模型，而不是保留最后模型。
- [ ] 测试集只用于最终报告。

## 当前答案

1. 类别不平衡不意味着模型一定学不到，但会让 Accuracy 失真，并增加训练和概率解释的难度。
2. 负采样降低计算成本，同时改变训练分布；测试集必须保留真实分布。
3. `pos_weight` 改变正样本对损失的贡献，但不自动保证概率校准。
4. AUC 衡量排序，LogLoss 和 ECE 衡量概率质量，不能互相替代。
5. LR 在高维稀疏场景中仍会过拟合。
6. L1 倾向产生稀疏权重，L2 倾向整体收缩权重。
7. Early Stopping 与正则化可以共同使用，模型选择只能查看验证集。
