# 03 · 多字段稀疏 CTR：LR / FM / MLP 对照

## 问题与范围

原先的 [FM 实验](../fm/README.md)只有五列稠密特征，适合检查二阶公式。这里加入长尾 ID 和多个类别字段，用**同一份数据、同一训练预算**比较 LR、FM、MLP。DeepFM 尚未实现；先观察 FM 分支和深层分支单独工作时的效果，后续组合才有可解释的基线。

## 数据协议

[`data.py`](data.py) 按 seed 生成模拟曝光。每行有六个类别字段：`user_id`、`item_id`、`user_segment`、`item_category`、`device`、`hour_bucket`；另有 `log_price`、`position` 两个数值字段。用户和物品 ID 服从长尾分布。隐藏的标签生成规律包含用户分群与物品类别的低秩匹配、用户/物品偏置、价格和位置效应；**匹配值本身不进入模型输入**。

默认生成 50,000 条，按生成顺序切为 35,000 / 7,500 / 7,500。生成器没有时间戳或漂移，这是模拟 IID 顺序切分。每个 seed 内三组模型获得完全相同的行、标签和切分；不同 seed 重新生成目录、偏好和标签，因此跨 seed 的 CTR 和任务难度会变化。比较时优先看同 seed 的配对差异。

类别词表**只使用训练集**的取值构建；每个字段各自保留本地 ID `0` 作为 OOV，再加字段偏移转换为全局 embedding ID。验证/测试中未见的原始 ID 映射到对应字段的 OOV。默认 seed 42 的训练词表含 OOV 共 1,023 个 token；验证集有 7 个未知用户 ID 曝光、2 个未知物品 ID 曝光。两个数值字段仅使用训练集的均值和标准差标准化。输入行均有固定字段，当前没有 PAD；PAD 只在后续变长历史序列中需要。

这是合成数据，不是实际曝光日志；用户分群与物品类别是生成器给出的静态字段。没有真实时间漂移、曝光策略偏差或冷启动协议。OOV 样本数量很小，本轮不能据此评估完整的冷启动能力。

## 三组模型

[`model.py`](model.py) 中的三组模型均接收相同的六个类别 ID 和两个数值特征，输出 logits，使用相同的 BCE 和评估函数：

| 模型 | 结构 | 本轮要回答的问题 |
| --- | --- | --- |
| SparseLR | 类别偏置之和 + 数值线性项 | 只靠一阶项能做到什么？ |
| SparseFM | 一阶项 + 所有活跃字段两两隐向量点积 | 二阶交互是否带来稳定收益？ |
| SparseMLP | 类别 embedding 拼接数值特征，再接 64→32 MLP | 深层非线性基线能否学到同类关系？ |

FM 的每行只有一个活跃 token/类别字段，计算的是活跃字段间及与数值字段间的二阶交互；它不是把所有词表 token 展成稠密 one-hot 矩阵。MLP 与 FM 都用 8 维 embedding，但参数总量不同；它们的差异不能仅解释为“有无二阶项”。

## 训练与复现

三组均使用 Adam、学习率 0.01、Batch Size 512、最多 25 Epoch、`patience=5`；按验证 BCE 保存并恢复最佳参数，再计算测试指标。seed 42 上比较公共学习率 0.01 与 0.003：LR、FM、MLP 各自的最优验证 BCE 在 0.01 下分别是 0.264910、0.261114、0.266425，在 0.003 下为 0.265140、0.262025、0.267204，因此固定 0.01。测试指标未用于选学习率。

```bash
uv run pytest -q
for seed in 7 42 2026; do
  for model in lr fm mlp; do
    uv run python -m models.sparse_ctr.train --model "$model" --seed "$seed"
  done
done
```

每次运行在 `outputs/sparse_ctr/<模型>/` 下创建独立目录，包含 `config.json`、`history.json`、`metrics.json`、`model.pt`。配置记录词表大小、OOV 计数、数据分布、标准化统计与环境；checkpoint 保存训练集词表和恢复后的最佳参数。运行产物未提交 Git。

FM 对 LR 的配对 AUC 提升为 +0.058009、+0.038673、+0.015504；配对 LogLoss 变化为 -0.013369、-0.005816、-0.000256。三个 seed 上 FM 的 AUC 和 LogLoss 均优于 LR。MLP 也有排序提升，但结果不如 FM 稳定；本轮不能断言 DeepFM 组合后一定继续提升。ECE 没有一致改善，概率校准需要单独检查。

所有模型很快达到最佳验证 BCE，继续训练时验证损失回升，尤其 FM/MLP 明显。这表明当前样本量、长尾 ID 和模型容量之间存在过拟合风险；后续可以用验证集选择 embedding 维度、正则化和更合理的用户/物品覆盖率。本轮不根据测试集调整模型。

不同 seed 的词表大小不同，参数量也略有变化。seed 42 的 LR、FM、MLP 分别有 1,026、9,226、13,561 个参数。训练耗时在本机约 0.7–1.9 秒，计时包含每轮验证、不包含数据生成；在这种小规模 CPU 实验里不作为工业推理成本结论。
